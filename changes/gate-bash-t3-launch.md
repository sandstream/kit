### Added

- **`gate-bash` refuses `t3 thread start`, `t3 thread send`, `t3 workflow start` and `t3 workflow resume` as nested-agent launches.** T3 Code starts the agent itself, at the project's default permission mode. That mode is Full access unless changed (Claude `bypassPermissions`, Codex `danger-full-access`), and no flag on these commands sets it, so an agent could start another agent that runs commands nobody approves. The commands passed with exit 0. They are now refused like `claude --dangerously-skip-permissions`, whatever their flags, including through `npx t3` and `sh -c`. The refusal says to have the person start the thread after lowering the default. Read-only subcommands (`t3 thread show`, `list`) still pass, and `agent-audit` reads a `Bash(t3 thread start:*)` grant as a nested agent with approvals off. Found by kit-research#241.
