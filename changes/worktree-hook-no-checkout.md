### Fixed

- **A worktree created with `git worktree add --no-checkout` (or `--orphan`) is now gated too.** The `post-checkout` hook that runs `kit worktree-gates` acted only when the previous HEAD was all zeros. `git worktree add --no-checkout` and `--orphan` run no hook at all, and the first checkout after `--no-checkout` passes the worktree's real HEAD, so the hook left at once and the worktree stayed ungated. That is the sequence T3 Code uses for every sparse worktree: `add --no-checkout`, then `sparse-checkout set`, then `checkout`. The hook now also runs kit at a checkout in a linked worktree (`.git` is a file) that has no `.claude/.kit-gates-installed` marker yet. Once the worktree is gated, later checkouts leave at once as before. The generated hook and this repository's `.githooks/post-checkout` both use only POSIX `case` and `test`. An existing generated hook is replaced on the next `kit agent-config`. Found by kit-research#241 (T3 Code).
