### Fixed

- **`kit ingest sarif` collapses repeated results into one finding with an occurrence count.** A report of 1,000 results over 250 distinct fingerprints showed 1,000 findings and dropped the fingerprint. Each finding now keeps it (SARIF `fingerprints`, else `partialFingerprints`, else a hash of rule, location and message) with `occurrences`, at the highest severity any copy had; the text header says `250 finding(s) from 1000 results`, and `--json` adds `results` when results collapsed. Scanner runs inside `kit check` count findings the same way.
- **`.kit-scan-results.jsonl` counts each `(source, id)` once.** 1,000 lines over 250 ids reported "1000 finding(s)"; they now report 250, each at the worst severity its records carried, and say how many records repeated an id. Records without an `id` still count one each. `docs/EXTERNAL_FINDINGS.md` no longer tells emitters that `id` is for their own dedupe.
- **`kit rig report` no longer calls a flooding reviewer "within spread" of a precise one.** A config producing 2,000 findings per run and one producing 1 had the same recall and were reported "within spread". Each config now prints duplicates per run and precision (defects caught per finding) beside recall, and when two configs' findings per run differ tenfold or more the comparison says recall alone does not compare them. These are counts from the adjudicated runs, not a judgement of either reviewer (ADR-0007).
