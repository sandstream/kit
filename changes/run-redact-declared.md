### Security

- **`kit run` now redacts every value declared in `[secrets.keys]` from its audit event, its command display and the child's output, whatever the key's name.** It only redacted values of env names that look secret (`KEY`, `TOKEN`, `PASSWORD`, ...) and at least 8 characters long, so a declared `DEMO_SIGNING_SALT` that `kit secrets` itself wrote to `.env.local` reached `.kit-audit.jsonl` in plaintext as part of `metadata.command`, against `docs/THREAT_MODEL.md`'s promise that the audit log never holds secret values. Declared values of 8 characters or more are redacted by substring as before; shorter ones, such as a 4-digit PIN, are redacted only where they stand as a whole token, so `4821` is redacted but `48219` is left alone. Values only secret-shaped by name keep the 8-character floor. Found by kit-research note kms-decrypt-evidence-vs-kit.
