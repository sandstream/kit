### Added

- **MCP tools that start or steer another agent are refused like a nested agent with its approvals off.** T3 Code gives its agents, and outside agents through `/mcp`, tools such as `delegate_task`, `t3_thread_launch` and `t3_thread_send`. These start agents at a permission mode the calling session cannot see, which is Full access by default. No kit matcher selected an MCP tool, and `gate-bash` let a payload with no shell command through. `kit agent-config` now wires `gate-bash` to those tools: in Claude Code as a PreToolUse group of its own, and in Codex as a second hook block, so the trusted `^Bash$` hook keeps its hash. `gate-bash` refuses them with exit 2. The tools covered are `delegate_task`, `t3_thread_launch`, `t3_thread_send`, `t3_thread_send_attachments`, `create_threads`, `schedule_task`, `run_scheduled_task_now`, and `t3_workflow` when its action starts, resumes or signals a run (an unknown action is refused too), on any MCP server. Codex runs the new hook only after you trust it, and the `codex install-gate trust` row names it until then. Found by kit-research#241.
