### Added

- **`kit secrets incident <backend>` prints an evidence plan next to the rotation plan: for each key, the command that fetches the store's own access record for it.** The rotation plan assumes every key was read, because kit had no read evidence; the stores often do. Per key it now prints, never runs: for `aws-sm`, CloudTrail `lookup-events` for `GetSecretValue` on the secret and for KMS `Decrypt` on its key, with the 90-day, one-Region Event history limit and the note that only a trail keeps more; for `gcp-sm`, the `AccessSecretVersion` Data Access log query, with the note that Data Access logs are disabled by default for all services except some BigQuery services; for `azure-kv`, the `SecretGet` AuditEvent query, which needs a diagnostic setting; for 1Password, the Events API item-usages call; for Infisical, the audit-log API filtered to `get-secret`. Each command was checked against the vendor page it cites. Vault, Doppler and Bitwarden get no command and are marked "not verified"; `env` and `config` keys have no store-side record. Every key also gets `kit audit secrets --key <NAME> --since <ISO>` for kit's own record. `--since <ISO>` fills in the start time. The plan states that a missing event proves only "not read through that service". Found by kit-research note kms-decrypt-evidence-vs-kit.
