### Security

- **`kit secrets incident` keeps its HMAC key outside the repo tree.** The fingerprint snapshot in `.kit/incident/<backend>.json` carried its own random HMAC key, so anyone who could read the file (a leaked tree, a backup, a synced folder) could test guesses for a value. The key now lives per user at `~/.kit/incident-keys/<project-id>/<backend>.key`, owner-only through `src/utils/secure-perms.ts`, never a symlink, and refused if it resolves inside the project. The project id is a hash of the repo root's native realpath, case-folded on Windows and macOS. The snapshot (format v2) holds only a key id, a domain-separated SHA-256 of the key. `--verify` fails closed, with no re-key, when the key is missing, widened, symlinked or malformed, when its id does not match the snapshot's, or when the project id cannot be determined. Only `--new-snapshot` replaces a key, and its audit row records the new `hmac_id`. A v1 snapshot (key inline) is refused; replace it with `--new-snapshot`. The OS keystore is not used: `src/keystore` is an Ed25519 signing port, not a secret store (kit-research#232). Tested on Linux; Windows runs in CI; macOS is unverified.
