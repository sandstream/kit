### Fixed

- **`kit triage skill <plugin>` reads the modules of a Claude Code mod.** A mod's `hooks/hooks.json` names JavaScript modules (`{"modules": ["./x.mjs"]}`) that Claude Code loads in its own process. Triage read that object as a hook event called `modules`, printed `modules hook (matcher '*')` and "0 hook command(s)", and never said where the module hooks in. It now reads each module's `on("<event>", {tool: …})` calls as text, never running them: a `tool.call` handler on Bash, Read, Edit, Write, MultiEdit or WebFetch (or on every tool, with no filter) is a warning, worded like a PreToolUse hook's, other events and `$.process.run` are listed, a module outside the plugin directory is refused, and the count is "hook module(s)". Found on Anthropic's claude-code-playground `blast-radius` mod, which holds Bash calls and was reported as matching every tool. Modules named beside `hooks` in the same file are read too (claude-plugins-official `claude-security` does this), and a tool filter given as a variable (`{tool: TOOLS}`) is reported as not evaluated rather than as every tool.
