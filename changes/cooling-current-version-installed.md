### Fixed

- **The cooling waiver recognises a security fix for a version installed without a lockfile.** A cooling check said "no current version known, so a security patch cannot be recognised" with 7.5.0 installed, because kit read the version in use only from the project lockfile. So `npm i -g` (and `kit upgrade --self`), a `node_modules` with no lockfile, every `kit triage pip` and every `gem install` held a first-fix security release for the full cooling period. kit now reads, in this order, the lockfile, npm's global install (`<prefix>/lib/node_modules` on POSIX, `<prefix>\node_modules` on Windows, the prefix taken from `npm_config_prefix`/`PREFIX`, the user `.npmrc` or the running `node`, without running npm), then `node_modules/<pkg>`; pip's `.dist-info/METADATA` in `python3`'s site-packages (names normalised per PEP 503); and gemspec names under `GEM_HOME`/`GEM_PATH` after `Gemfile.lock`. A version read from an installed copy counts only when the registry has published it, feeds the waiver only, and never skips the cooling period as a lockfile pin of the same version does. The cooling line says where the version came from ("current 7.5.0 from the global install"), or names the sources it checked. macOS is unverified.
