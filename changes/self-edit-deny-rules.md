### Security

- **The gates now refuse an agent's write that removes one of kit's deny rules or adds an allow rule that undoes one, as they already did for kit's gate hooks.** An agent's Edit that deleted `"Read(~/.aws/**)"` from `.claude/settings.json` passed `gate-env` with exit 0, while an Edit to the gate hook in the same file was refused. `gate-env` now refuses a Write or Edit to `.claude/settings.json`, `.claude/settings.local.json` or `~/.claude/settings.json` that removes one of the twelve deny rules `kit agent-config` writes, or adds an allow rule that matches one (such as `Bash(git push:*)` or `Read(~/.ssh/**)`). It also refuses a write to a Codex rules file (`.codex/rules/*.rules`, `~/.codex/rules`, `$CODEX_HOME/rules`) that adds a `prefix_rule` with decision `allow` or none, since Codex defaults it to `allow`. `gate-bash` refuses shell writes (`>`, `tee`, `sed -i`, `cp`, `mv`, ...) onto a Codex rules file, and onto a settings file that holds kit's deny rules even without a gate hook. A rule a harness writes itself, such as Claude Code's "don't ask again", passes no gate. Found by kit-research#239.
