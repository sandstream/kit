### Added

- **`kit gha-audit` flags a long-lived cloud key where OIDC would do.** A deploy workflow that passed a stored AWS key pair to `aws-actions/configure-aws-credentials` named the keys only inside the install-scripts row. A new row, `static <cloud> key on job <id>`, fires in four cases: `aws-access-key-id` / `aws-secret-access-key` given to `aws-actions/configure-aws-credentials`, `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` set from `${{ secrets.* }}` in an `env:` (at workflow level the row is `workflow-level static AWS key`), `credentials_json` given to `google-github-actions/auth`, and `creds` given to `azure/login`. The suggestion names the provider's OIDC inputs (`role-to-assume`; `workload_identity_provider`; `client-id`, `tenant-id` and `subscription-id`), `id-token: write` on that job only, and the provider's OIDC guide. It is the pair to the `id-token` rows: those flag OIDC granted where nothing uses it, this one flags a stored key where OIDC would do. Found by kit-research#239.
