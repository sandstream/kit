### Fixed

- **Declarative `.kit/standards.d` rules read dot-directories such as `.github/`.** The shared source walker skipped every directory whose name starts with a dot, so a rule over `.github/workflows/*.yml` reported "no matches" on a file it never read, and nothing said so. Plugin rules now walk dot-directories and skip only `.git`, kit's own `.kit`, and dependency and build caches (`.venv`, `.cache`, `.yarn`, `.turbo`, …); dotfiles stay skipped. Other commands that use the walker are unchanged. A baseline frozen before this may see new matches in dot-directories.
- **A `require` rule whose `scope` matches zero files no longer passes.** It printed "✓ required pattern present in scoped files" and passed under `--enforce`, though it had checked nothing; the "scope regex matched zero files" warning only appeared when the rule's extensions matched some file. It is now reported once as incomplete (a warning, counted as a setup gap), and fails under `--enforce`. The same holds for a `require` rule with no file of its extensions.
