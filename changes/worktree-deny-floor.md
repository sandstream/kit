### Fixed

- **A new git worktree now gets kit's deny rules and sandbox block, not only the gate hooks.** `kit worktree-gates` (run by the `post-checkout` hook when git creates a worktree) installed the PreToolUse gates but never the deny floor `kit agent-config` writes into `.claude/settings.json`: twelve deny rules (credential directories, `.env*`, force push, `git reset --hard`) and `sandbox.enabled` with the credential `denyRead`. That file sits in the ignored `.claude/` in most projects, so an agent started in a new worktree could read `~/.ssh` or force-push where the main checkout refused it. When the main checkout has the floor, the worktree now gets the same merge, and `kit worktree-gates` reports a failure if any rule is still missing afterwards. A main checkout without deny rules still imposes none. Found by kit-research#241 (T3 Code).
