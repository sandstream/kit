### Added

- **A `.kit/standards.d` rule can say why, and kit lists the rules agent skills state that no rule checks.** An optional `because` is printed with each failure (`… 1 new match(es) (1 total). Because: ids are domain primitives; call ProductId.New()`), so the agent that broke the rule reads how to fix it, as ArchUnit's `because` does. The plugins stage adds a warning, `skill rules without a gate`: a line in `.claude/skills`, `.agents/skills` or `.codex/skills` that states a rule (never, always, do not, forbid, aldrig …) about a code token in backticks that no standards rule finds or names. Such a rule holds only while the agent reads and follows the skill. The warning never fails and does not ask to remove the skill line, which still helps the agent get it right the first time. Text over text, no model.
