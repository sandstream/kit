### Security

- **A gate that faults while loading modules now denies with exit 2 instead of exiting 1.** The fault deny in `runGateFailClosed` loaded `node:fs` with a dynamic import before it wrote the deny, so when module loading was the fault the deny threw too and the process exited 1, which Claude Code, Codex and the other PreToolUse harnesses treat as a non-blocking error: the tool call ran. A V8-snapshot build showed it on every payload (kit-research#233, E3). The deny now uses a static `writeSync` and `process.stderr`, falls back to a fixed line if writing the reason throws, and exits 2 either way; Cline and Antigravity get their stdout-JSON deny. A fault in the CLI's dispatch steps before a gate's handler (the read-only floor's imports, policy load) also denied nothing: it exited 1 through the generic error path. For a gate verb it now denies with exit 2 as well. A fault while loading `cli.js`'s own static imports still exits 1, before any kit code runs.
