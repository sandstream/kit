### Added

- **`kit triage release <url|file>` checks a prebuilt release archive or binary before it is extracted, run or put on PATH.** Five checks, each `pass`, `fail` or `unverified` as `kit triage pkg` reports them: SHA-256 against `--checksum` or the publisher's checksum files next to the asset (`checksums.txt`, `SHA256SUMS`, `<asset>.sha256`, and GitHub's own asset digest; sources that disagree fail); a minisign or cosign signature verified with node:crypto and a key you name (`--minisign-key`, `--cosign-key`), never a key taken from the release, with OpenPGP and keyless Sigstore reported `unverified`; a GitHub release's age through the same cooling period as packages (a `releases/latest/download` URL and a draft fail); its repository against `--repo owner/repo` and against the repository GitHub actually serves it from; and every member of a tar, tar.gz or zip, failing absolute paths, `..`, symlinks or hard links out of the tree, setuid and setgid bits and device entries (xz, bzip2 and 7z are `unverified`: kit ships no decompressor for them). It passes only when every `unverified` check is named in `--accept-unverified`, so an unsigned release is never a silent pass. A pass for a URL records a `release` receipt in `.kit-triage.jsonl` with the file's digest. Nothing from the file is executed; a download goes to a private temporary directory and is removed. Found by kit-research#233 (G1).
