# The rig (v1) Implementation Plan

> The command below is written as the bare verb (`rig`) because it does not exist yet, and kit's
> docs-claims audit refuses a command-form reference to a verb that does not dispatch.
> Phase 4 switches this document to the full form in the same PR that ships the command.

> Steps use checkbox (`- [ ]`) syntax for tracking. Each phase lands as its own PR with green
> CI before the next starts.

**Goal:** Ship the rig that [ADR-0007](../adr/0007-kit-owns-the-rig-never-the-judgement.md)
accepted but kit never built. It answers, with numbers, _"does this prompt, policy or rule
change make the reviewer better?"_:

- a frozen input;
- an ingest of a reviewer's findings;
- deterministic adjudication against planted defects;
- caught/missed/false-positive arithmetic across repeated runs;
- signed receipts.

kit never runs the reviewer. The model runs outside kit and hands its findings in.

**Why now:** ADR-0007's own _Implementation status_ says there is "no `rig`, ingest, or
adjudicate command". Meanwhile kit writes agent rules into other repositories (`kit agent-config`, the managed `CLAUDE.md`/`AGENTS.md` block) and has never measured whether they help.
Outside evidence says such changes routinely fail measurement:

- **A practitioner's planted-bug eval.** A practitioner running an agent "software factory"
  reported, on 75 planted bugs, that an 850-line review policy caught 26 against 38 with no
  policy, 200 lines caught 59, and one added prompt sentence caught 71. Those were single runs,
  recall only, from a single source. Analysis:
  `sandstream/kit-research/docs/research/factory-metrics-planted-bugs-and-the-rig.md`.
- **Anthropic's code-review write-up.** It recommends short `REVIEW.md` files, and turns
  incidents into the eval its reviewer runs against daily.

The direction is plausible. The rig is how kit finds out for itself instead of borrowing
someone's numbers.

**Tech stack:** TypeScript (ESM, `.js` specifiers), Node 22+ `node:test` + `node:assert/strict`,
the existing hash-chained audit log (`src/audit.ts`) and identity signing (`src/identity.ts`).
No new runtime dependency (ADR-0002) and no model client (ADR-0001).

## Decisions taken as defaults (change them in review)

| Decision                  | Default                                                                                  | Why                                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Command name              | `rig` with subcommands `plan`, `ingest`, `adjudicate`, `report`                          | The ADR already speaks of "the rig"; one noun keeps the surface small                                                                 |
| Where defect corpora live | **Outside this public repo**, in a private repo or a local folder the manifest points to | ADR-0007 limit 2: the corpus "must never be published as a benchmark", and a public corpus becomes the thing models are tuned against |
| First workload            | kit's own agent rules (phase 6)                                                          | It answers the question kit cannot answer today, about a claim kit makes to every repo it configures                                  |

## Global constraints

- **Zero-LLM.** No model call and no model SDK anywhere in `src/**` (ADR-0001's `forbid_import`).
  Every number is reproducible from the frozen input plus the ingested files.
- **The three ADR-0007 limits ship in the output, not only in docs.** Every `rig report` prints:
  1. _Lower bound only_: it measures only what was seeded; it is never a safety score.
  2. _Goodhart_: the corpus must rotate and is never a benchmark.
  3. _Transfer is unproven_: a number for one repository and corpus does not carry to another.
- **Public repo.** No third-party names, customer names or private hosts in code, tests,
  fixtures or commits. Fixtures use generic names (`acme/webapp`).
- **Cross-platform.** Paths through `node:path`, and reported paths use `/`. Tests skip on
  `win32` only with a reason (see `CLAUDE.md`). CI covers Linux and Windows, not macOS.
- **Size and complexity ratchets.** New files stay under 600 lines, functions under CCN 15 and
  80 lines. Never edit `.kit-baseline.json` to admit growth.

## Phase 1: formats (pure, no command)

New `src/rig/manifest.ts`, `src/rig/findings.ts`, plus tests. **Done.**

- [x] **Manifest** (`rig.toml`) with these fields:
  - `[input] repo`, `commit` (full SHA), `prompt` (path to the reviewer prompt or policy under
    test);
  - `tolerance` (lines, default 3);
  - `[[defect]] id`, `file`, `line_start`, `line_end`, `kind`, `split = "tune" | "holdout"`,
    and `patch` (path to the diff that plants it);
  - `[[control]] id`, `patch`: a clean diff with no planted defect.

  Parse into a typed object, reject unknown keys, and refuse a defect without `split`.

- [x] **Input id** = SHA-256 over the canonical manifest, the prompt bytes and every patch's
      bytes. Two runs with the same id answered the same question.
- [x] **Findings ingest** (JSONL, one finding per line):
      `{ run, config, file, line, claim, severity, model, model_version, date }`.
  - Validate each row. A malformed row is reported with its line number and never skipped
    silently; with `--strict`, the whole file is refused.
  - `file` is normalised to `/` and repository-relative.
- [x] Tests:
  - the canonical-hash stability across key order and line endings (`\r\n` vs `\n`);
  - rejection of unknown keys and a missing `split`;
  - row validation messages.

## Phase 2: adjudication (pure, deterministic)

New `src/rig/adjudicate.ts`. **Done.** A run reviews one target (a defect or a control), named by the finding's `target`; a finding that matches an already-caught defect counts as a duplicate, neither caught again nor unmatched.

- [x] A finding **catches** a defect when `file` matches and `line` lies within
      `[line_start - tolerance, line_end + tolerance]`. Each defect is caught at most once per run.
      A finding matching two defects counts for the nearer one, and ties go to the lower `id`.
- [x] A finding on a **control** run is a **false positive**. A finding on a defect run that
      matches no defect is **unmatched**: reported, but not counted as a false positive, since it
      may be a real pre-existing bug.
- [x] Output per run: caught ids, missed ids, false-positive count, unmatched count.
- [x] Tests, table-driven:
  - edge lines at the tolerance boundary;
  - two findings on one defect;
  - one finding between two defects;
  - control runs;
  - Windows-style paths in findings.

## Phase 3: repeated runs, spread and splits

New `src/rig/report.ts`.

- [ ] Aggregate N runs per `config`:
  - recall (mean, min, max);
  - false-positive rate on controls (mean, min, max);
  - per-defect catch frequency.
- [ ] **Comparing two configs.** A difference is called _outside run-to-run spread_ only when
      the configs' `[min, max]` recall ranges do not overlap. Otherwise the report says _within
      spread_. This is deterministic and conservative, with no statistics the reader has to trust.
      Refuse to compare when either config has fewer than 3 runs.
- [ ] **Splits.** Report `tune` and `holdout` separately. Warn when only `tune` was run, or when
      a config was changed after its last `holdout` run (detected by the input id).
- [ ] Tests:
  - the overlap rule;
  - the 3-run floor;
  - the holdout warning;
  - stable ordering of the report.

## Phase 4: the command and receipts

New `src/commands/rig.ts`, wired in `src/cli.ts`.

- [ ] Subcommands:
  - `rig plan <rig.toml>`: validate the manifest, print the input id, and print exactly what
    to run outside kit (the commit to check out, the patch to apply per defect or control, and
    where to write findings);
  - `rig ingest <findings.jsonl>`: validate and store the findings under
    `.kit/rig/<input-id>/`;
  - `rig adjudicate`: run phases 2 and 3 over the stored findings;
  - `rig report [--json]`: print the report with the three ADR-0007 limits verbatim.
- [ ] **Receipts.** Each `adjudicate` appends one audit event through `logAuditEvent` with the
      input id, the SHA-256 of each findings file and the result summary. When an identity exists,
      the summary is signed with `signWithIdentity`. The receipt can be replayed: the same input id
      and findings hashes give the same numbers.
- [ ] Wire-up chores the gates require:
  - an entry in `src/help-categories.ts` (the group test fails otherwise);
  - entries in `src/subcommand-help.ts` for each subcommand;
  - a row in `docs/COMMANDS.md`;
  - regenerate `src/flag-surface.ts`, `contracts/kit.opencli.json` and
    `contracts/public-surface.json` with their scripts;
  - a CHANGELOG entry.
- [ ] **Read-only mode.** `ingest` and `adjudicate` write under `.kit/rig/`, so classify them in
      `src/read-only-surface.ts` the way other `.kit/` writers are.
- [ ] Tests:
  - a CLI end-to-end run on a tiny fixture repo (two defects, one control, three runs per
    config), with snapshot of `--json`;
  - an audit event written with the expected hashes.

## Phase 5: planting defects deterministically (optional helper)

- [ ] `rig plant --from-fix <sha>` (or a script under `scripts/`): turns a historical fix
      commit into a defect by reversing its diff onto the pinned commit. The defect's
      `file`/`line_start`/`line_end` come from the reversed hunk. No model is involved. This follows
      the "incidents become evals" practice: real past bugs are better seeds than invented ones.
- [ ] Refuse a fix whose reverse does not apply cleanly on the pinned commit. It must never be
      guessed.

## Phase 6: first workload — do kit's own agent rules help?

Run outside kit, recorded through the rig. No kit code beyond phases 1–5.

- [ ] Build a corpus from kit's own history. Use 40–75 defects from reverted fix commits
      (phase 5), split roughly half and half into `tune` and `holdout`, plus at least 10 clean
      control diffs. Store it in the private corpus location, not in this repo.
- [ ] Compare three reviewer configs, at least 3 runs each:
  - (A) no project rules;
  - (B) only the kit-managed block;
  - (C) the full `CLAUDE.md`.
- [ ] Record the result in `sandstream/kit-research`, with the report's three limits quoted.
- [ ] If (B) or (C) does not beat (A) outside the spread, open an issue to shorten what
      `kit agent-config` writes. That is the measured claim this whole plan exists to test.

## Done when

- `rig plan|ingest|adjudicate|report` ship, with the tests above, on Linux and Windows CI.
- ADR-0007's _Implementation status_ section is updated in the same PR as phase 4, from "not a
  shipped command surface" to what shipped.
- Phase 6 has a recorded result, whichever way it points.

## Out of scope

- Running any model, ranking models, or grading a review's quality (ADR-0004, ADR-0007).
- Publishing a corpus or a leaderboard (ADR-0007 limit 2).
- Statistical tests beyond the min/max overlap rule. A later version may add them only if the
  overlap rule proves too blunt in practice.
